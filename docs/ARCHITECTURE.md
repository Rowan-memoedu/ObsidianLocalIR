# Local IR：实现机制与开发意图对照

本说明覆盖 0.9.0。意图从既有 README、CHANGELOG、状态合同和回归测试还原；它不是新增产品规划。源码保留迁移前 0.8.9 的用户改动，0.9.0 只做职责拆分、状态安全、性能与工程交付修正。

## 1. 产品要解决什么

- 把“已准备好的 Markdown”变成可反复返回的阅读队列，让读者在多篇文章之间按价值、密度、难度、兴趣推进。
- 阅读和加工低摩擦：选区即标注，正文默认不改；加工内容和源文分开保存。
- 从阅读中沉淀批注、挖空、QA、随想，同时明确不同内容的后续去向。
- 本地工作可持续、可恢复；导出只是准备材料，远端正式归档必须有另一工程的成功回执。
- 非目标：本插件不是 FSRS/间隔重复算法，不负责网络采集质量、浏览器登录或 RemNote 正式写入，也不自动替用户生成缺失观点。

## 2. 代码与数据的职责

- `main.ts`：Obsidian 生命周期、阅读池/文件操作、文档状态导入回写、阅读操作、加工动作与导出适配。保留既有公开方法，避免破坏共享核心和 Canary 的调用合同。
- `types.ts`：文章、指标、标注、QA、随想、导入队列及导出载荷类型。
- `model.ts`：默认配置、规范化、日期/排期辅助、Markdown 安全范围/层级、加工路由与兼容序列化辅助。
- `sidebar.ts / modals.ts / settings.ts`：侧栏、加工/确认弹窗、配置界面；通过插件公开方法发起动作。
- `editor-integration.ts`：CodeMirror 装饰、文档位置映射、快捷键优先级；`reading-highlights.ts` 负责原生阅读视图的 DOM 文本与源文坐标映射。
- `metric-presets.ts / priority-scheduling.ts / editor-gestures.ts / archive-text.mjs`：独立可测的指标初始化、极高优先级、手势与线性文本扫描。
- `async-work.ts / document-state.ts`：串行合并任务、sidecar 路径身份、按文档建立加工数据索引。
- `batch-archive-backend/`：独立纯 IO 注入生产者、native-v2 schema、journal 与冻结输入合同。
- 外部已有依赖 `../渐进阅读工作流/document-core`：标注标准化、无损合并、增删、撤销重做、锚定、文档状态合同；运行时随 bundle 打包，不要求 Obsidian 在运行时加载另一个源码目录。

主入口由原来的约 7,100 行缩为约 3,800 行；拆分没有改变排期参数、CSS、加工类型和生产者并发策略。三个无引用的旧 helper 已移除；仍可能被适配器调用的公开导出方法保留，不以“清理”为由删除兼容入口。

### 数据权威

- Vault Markdown：可阅读的原文；经典 mark/旧 `==高亮==` 兼容例外，虚拟高亮不写入正文。
- 插件 `data.json`：配置、文章记录、指标、加工记录和待导入请求的持久存储；数据格式版本仍为 14，本次不做批量数据迁移。
- 关联 `.browser-ir.json`：该文档的跨端加工状态权威。导入后成为插件内存副本，本地加工递增 revision 并回写；以 revision、updatedAt、内容指纹识别已同步内容。
- 队列 package/journal：冻结输入及生产结果；不是可随意重写的另一套笔记库。
- 正式归档 receipt：只有下游成功写入并回读后才证明 `archived`。

## 3. 阅读池与排期

- 意图：阅读池是“哪些文章参与排期”的配置，不是文章数据的生死开关。
  - 实现：`syncRecords` 枚举配置目录下的 Markdown，跳过以 `FAILED ` 开头的失败材料，新增记录并补读指标；刷新已有标题和优先级。
  - 修正：移除文件夹或临时失去索引时保留记录、批注、QA、随想。只有在池内且索引可用的文件才进入可读候选；找不到的文件不会被“继续阅读”选中。
  - 明确保留边界：持久数据不自动垃圾回收，长期消失的原文可能留下记录；清理是独立、需要明确对象的操作。
- 意图：价值和兴趣引导阅读，但不能只盯最高分。
  - 五档为 `0 / 2.5 / 5 / 7.5 / 10`。四项字段与 UI 为 `importance=价值判断`、`urgency=信息密度判断`、`difficulty=难度`、`interest=兴趣`；`urgency` 是兼容旧数据的历史字段名，不再按“紧急程度”解释。
  - 默认权重 `40 / 20 / 15 / 25`，加权平均得到 priority；难度正向计分，这是既有规则，本轮未自行改成“容易优先”。
  - 四项全为 10 时先选极度重要文章；否则默认 20% 选最高分，80% 按 `max(priority, 0.1)` 加权轮盘。
  - 默认排除当天已访问；Later 到期前、搁置、读完、包已准备、已归档均不参与。不自动把 Later 当遗忘曲线。
- 意图：自动初始化提供起点，人工判断拥有更高优先级。
  - 读 `阅读前置卡`/兼容 frontmatter；sidecar 先到、Markdown 后到时可补读一次。
  - `metricsEditedByUser` 永久保护手调；mtime 检查防止重复扫描，旧非默认值按可能人工调整保护。
  - 证据：metric preset、initialization race、priority scheduling 测试和独立合成 Canary。

## 4. 阅读与加工

- 意图：标注不破坏正文格式。
  - 默认用虚拟范围；CodeMirror 装饰及原生阅读视图 CSS Highlight 绘制。阅读视图以 section 源文偏移消除重复段落歧义；渲染正文过期则拒绝创建错误坐标。
  - 代码、公式、HTML/style、图片和链接受保护；经典模式只对安全范围写 mark。旧 `==高亮==` 首次保存才升级。
  - 整行加工只在 Ctrl 单击时触发，范围是点击所在的编辑器逻辑行，不扩到相邻 Markdown section。
  - 完整选中标题/列表父项才扩展子树；部分选区保持普通选区，导出时重算当前层级。
  - 修正：渲染侧栏不再隐式调用“危险 mark 修复”；改动原文必须来自明确加工/修复操作。
- 意图：合并和撤销不能吞掉既有思考。
  - 共享核心负责 ID、离散范围、评论/改写片段的无损合并；左 Alt 多选后合并；自动同块合并仍默认关闭。
  - 虚拟修改记录前后 change，最多保留最近 20 次；Ctrl+Z/Ctrl+Y 优先于原生编辑器快捷键，仅拦截可安全撤销的虚拟动作。
  - 快照过期、跨文档、不同 mark 类型、冻结输入被拒绝；无关标注的新改动不被整份旧快照覆盖。
- 意图：草稿低摩擦保存，正式数据有明确去向。
  - 标注弹窗约 700ms 防抖保存类型、评论、改写；QA 和随想由各自按钮提交。
  - 普通/迷思真相/引用/联想/优化/例子观点进入对应加工载荷；QA 进入卡片；提问进入问题队列；无实质评论的普通高亮进入精炼阅读；挖空单独形成 cloze 载荷。
  - 虚拟标注的“改写”改加工记录/导出文本，不静默改原文。生成答案标志只是下游请求，不代表插件已生成答案。
  - 修正：草稿只刷当前文档 sidecar，不每次自动保存重建整个侧栏；关闭弹窗后再刷新展示。
  - 证据：真实插件方法的共享核心适配测试、手势/样式基线、原生 DOM Canary 的 12 个场景及零正文写入。

## 5. 状态同步与可靠性

- 意图：两个同名文章的状态不能串线。
  - 新状态路径包含完整 Markdown 路径的 SHA-256 截断身份；已有平铺/相邻 sidecar 可读，读取前核对内部 `document.path`。
  - 托管文件移动屏蔽重复异步 rename 事件，显式顺序完成路径关联；旧平铺 sidecar 保留稳定文件身份，仅更新内部文章路径。
  - 指标属于插件记录，不被 sidecar 导入覆盖；Later 到期日随状态导入/回写。
- 意图：保存按钮完成，就不能漏掉保存期间发生的下一次修改。
  - `CoalescedAsyncTask` 对 data 保存、sidecar flush、视图刷新串行合并；执行中到来的请求会再跑一轮，所有等待者在队列排空后结束。
  - 每轮按文档路径归组标注/QA，避免每篇文章都扫描全部加工集合；常见编辑指定 `documentPaths`。
  - 未关联 sidecar 的已有文档不再无条件读取 Markdown；关联文档以 sidecar stat 和正文 mtime 缓存扫描结果。
  - 数据 save 的失败传回调用方，后续请求可重试；sidecar 写入失败保留待刷新路径。桌面 adapter 下使用临时文件+rename。
- 验证：状态回归覆盖池移除保留、候选筛选、同名身份、归属拒绝、旧路径兼容、100 篇无 sidecar 的零正文读取、并发写入最终状态、定向刷新、冻结保护、rename 顺序、失败重试和草稿不重建侧栏。
- 边界：这是单个 Obsidian 实例内的串行保存，不是跨进程分布式锁；外部生产者同时修改同一 sidecar 仍按既有权威合同同步，本轮未引入新的跨端合并协议。

## 6. 完成阅读与导出

```text
inbox / reading / 到期 later
        ↓ 完成阅读，原文移到 staging
      done
        ↓ 单篇或批量生成；冻结输入、写 journal、校验去向
export_package_ready
        ↓ 下游正式写入 + 回读 + 成功 receipt
     archived
```

- `done` 可恢复阅读，原文移回阅读池；commit 后冻结，不能通过草稿、恢复、状态更新或修复绕过。没有实现安全撤回合同，因此不允许直接撤销已排队的包。
- UI 防止单篇重复点击与单/批量交叉执行。生产者默认一候选一路异步任务，可显式限流，结果确定排序；本轮保留这一既有产品选择。
- journal 先记 writing，再存冻结输入摘要、写 Markdown 与派生产物，最后写 native-v2 JSON commit marker；相同输入幂等重放，崩溃可恢复，非本 package 路径冲突拒绝覆盖。
- 没有 RemNote import item 时必须明确确认缺失内容；取消保持 done、不记失败，不把仅精炼/提问输出伪装成正式可导入内容。
- 失败记录保留 code/kind/reasonCode/errors，不记录正文；一篇失败不阻断其他篇。
- 证据：15 项后端测试、与正式 importer byte-identical 的 schema 校验、合成 package 经下游 normalize/validate 并幂等重放。没有调用真实 RemNote 写入。

## 7. 外部接口与范围

- 待导入列表保存规范化 URL、来源路径、请求 ID、状态/错误；标准请求由本地共享服务执行，插件只提交/轮询回执、断线重试并在重载后续接。
- HTTP 202 只是受理；“已生成但有瑕疵”与失败、需要登录/JS 渲染分别展示。
- 本轮仅保留并验证接口接线，未改抓取器/扩展/共享核心/正式导入器，未触发真实网络导入或用户材料外发。
- 旧真实材料诊断脚本具有 12 篇/7 篇历史样本前提，已修正路径与产物位置，但不列作默认通用验收。

## 8. 工程交付与验收解释

- 活动源码独立 Git 仓库，只有 main/origin/main；迁移前工作树完整哈希核验并保留可恢复隔离副本，旧入口只是 junction。
- 构建版本从 manifest/package 核对后生成 banner；只写 D 盘产物目录，不猜 Vault 相对位置、不自动部署。
- 部署要求绝对 Vault，只覆盖三份运行文件，前后 SHA-256 回读，保留旧运行文件；不读写式规范化 data.json，不改社区插件启用列表。
- 普通回归：8 个入口脚本 + 32 项 node:test（15 后端、14 状态、3 部署）；额外严格 TypeScript 检查、生产构建、独立指标/归档 Canary。
- 共享集成：纯核心、真实插件方法适配、隔离服务到真实导入方法的 handoff；都不需要生产内容。
- 原生验收：CLI 在真实 Obsidian DOM 中运行独立合成文档，覆盖阅读标注和三组主题配色；同时检查 data.json、活动文件、选区不变。机器回执记录候选版本和已加载版本，二者不能混为一谈。
- 未覆盖承诺：不宣称所有插件组合/Obsidian 未来版本零回归，不把隔离 Canary 当成真实 RemNote 已归档，不把已部署文件当成运行实例已重载。

本轮恢复的是既有意图与代码的一致性，没有更换排期算法、重新设计界面或扩张到外部生产系统。
